Coverage: the Latin1 split is U+0020-U+007E, U+00A0-U+00FF plus the typography
the design already uses (U+2013/U+2014 dashes, U+2018-U+201E quotes, U+2026
ellipsis, U+2212 minus, U+20AC euro). It does NOT carry U+25B2/U+25BC (the
`.sort-indicator` triangles) or U+21B5 (the editor's return glyph); those fall
back per-glyph to the system stack that follows IBM Plex in --font-sans /
--font-mono. The all-script "complete" faces would cover them at 410080 bytes
(400 KiB) raw — 2.9x the payload — so the Latin1 subsets ship instead.

Delivery: crates/openkite-ui/assets/main.css declares each face with the URL
the browser host serves it from (`/assets/fonts/<file>`, served by
`crates/openkite-web/src/routes.rs::font_get`). The desktop window has no
origin to serve them from, so it inlines `openkite_ui::assets::embedded_css()`
instead — the same stylesheet with each face URL replaced by a `data:` URI.
Base64 costs 4/3 of the raw bytes, so the desktop head carries ~182 KiB of
inline font data; an SSR page is unaffected (a few hundred bytes of CSS, then
one cached fetch per face).

Rebuild: re-download at the pinned commit, e.g.
  curl -sSLo ibm-plex-sans-400.woff2 \
